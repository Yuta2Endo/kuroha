# Протокол: DeepSeek + Haiku над Kuroha

Две модели, один репозиторий. **DeepSeek V4.1 Flash** пишет код.
**Claude Haiku 5.5** принимает визуальные решения. Правила проекта — в
`AGENTS.md`, они старше любого совета дизайнера.

Режим работы выбирается один раз на сессию:

- **субагент** — DeepSeek сам запускает Haiku на `claude-haiku-5-5` для
  каждого дизайн-шага;
- **вручную** — DeepSeek выдаёт бриф, человек относит его в Haiku и
  возвращает ответ.

## Роли

| DeepSeek | Haiku |
|---|---|
| Разметка, CSS, JS, сервер | Диагноз и правки внешнего вида |
| Массовые правки по страницам | Состояния: hover, focus, empty, error |
| Проверка тем, адаптива, консоли | Ритм, отступы, типографика, контраст |
| Коммиты и отчёт | Ревью diff и скриншота |

Haiku **не пишет код**. Её ответ — таблица правок: селектор, свойство,
значение, зачем. DeepSeek реализует и отвечает за результат.

## Цикл — одна страница за раз

1. **Контекст.** `tokens.css`, `page.html`, `page.css`, 1–2 соседние
   страницы, `git status`. Ничего лишнего: 46k строк в контекст не лезут.
2. **Baseline.** Список фактов без вкусовщины: хардкод цветов, недоступный
   контраст, горизонтальный скролл на 360, отсутствие `focus-visible`,
   пустое состояние, битые ссылки, неиспользуемые токены.
3. **Бриф Haiku** по шаблону ниже. Только эта страница.
4. **Решение Haiku.** Правки с селекторами, токенами и значениями.
5. **Фильтр по `AGENTS.md`.** Выкинуть: новые токены без нужды, новые
   компоненты, переписанные тексты, выход за скоуп. Отклонённое — в лог.
6. **Реализация.** `page.html` + `page.css` (+ `page.js`). `styles.css` —
   только если компонент нужен трём и более страницам.
7. **Проверка.** 1280 и 360 px, темы night / paper / graphite, пустой
   localStorage, чистая консоль. Менялся общий файл — поднять `?v=`
   и `CACHE_NAME` в `sw.js`.
8. **Коммит.** `design: <page> — <суть>`.
9. **Ревью.** Haiku получает только `git diff` и скриншот. Говорит
   «принять» или «переделать пункты N». Максимум две итерации, дальше
   решает человек.
10. **Отчёт.** Что изменил, что отклонил и почему, что осталось.

## Жёсткие границы

- Навигация, футер и тексты — только по прямой команде.
- Соседние страницы не рефакторить «заодно».
- Зависимости, сборка, второй шрифт — запрещены.
- `server/` вне скоупа дизайн-цикла.
- Больше 12 правок на страницу — разбить на два цикла.
- Скриншот обязателен: без него Haiku советует «добавить воздуха» без чисел.

## Бриф для Haiku

```text
Ты — дизайнер проекта Kuroha. Ты не пишешь код, ты принимаешь решения.
Стиль задан и не обсуждается: Exo 2, палитра ink/paper/red, тон тихой
ночной библиотеки. Новое направление не предлагай.

Контекст:
- tokens.css: <блок :root>
- страница: <HTML>
- её стили: <page.css или нужные секции styles.css>
- скриншот: <путь к PNG>

Задача: <страница/блок>.

Ответ строго так:
1. Диагноз. 3–5 проблем, по строке, с селектором. Только то, что видно
   в разметке и стилях.
2. Правки. Таблица: селектор → свойство → значение → зачем.
   Значение — существующий токен --kh-*. Если токена нет, написать
   «нужен новый токен: <имя>», а не подставлять число.
3. Состояния. Чего нет из hover / focus-visible / active / disabled /
   empty / error. Только для этой страницы.
4. Адаптив. Что на 360 и 768, что поедет.
5. Темы. Что сломается в paper и graphite.
Ограничения: максимум 12 правок, тексты не менять, новые классы —
только модификаторы к существующим блокам.
```

## Чеклист перед сдачей

- [ ] 1280 px и 360 px — нет обрезанного контента
- [ ] night, paper, graphite — читаемо
- [ ] пустой localStorage — нет пустых дыр вместо контента
- [ ] клавиатура: Tab, Enter, Esc, видимый фокус
- [ ] консоль чистая
- [ ] `git diff` только по целевым файлам
- [ ] `?v=` и `CACHE_NAME` подняты, если менялся общий файл

## Лог решений

Ведётся в `DESIGN-LOG.md`: страница, дата, что предложила Haiku, что
принято, что отклонено и почему. Нужен, чтобы через десять страниц не
спорить об одном и том же заново.

## Настройки моделей

- DeepSeek — вариант `high`. `low` только на боилерплейт.
- Haiku — вариант `high`. `max` на вёрстку не влияет, только на цену.
