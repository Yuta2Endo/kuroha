# AGENTS.md — Kuroha

Правила для AI-агентов и людей, которые правят этот репозиторий. Читать перед любой задачей.

## Что это

`G:\Developing\kuroha` — статический прототип библиотеки манги, манхвы, маньхуа и новелл.

- `prototype/` — весь фронтенд: **35 HTML-страниц, ~19 400 строк CSS, ~15 800 строк JS** (~45 800 строк всего).
- `server/` — локальный Node API v0.1 на голом `node:http`, без зависимостей.
- Стек: чистый HTML/CSS/JS. **Никакой сборки, npm, бандлера, TypeScript, фреймворка, препроцессора.**
- Бренд: **Kuroha 3.0** — шрифт Exo 2, палитра Ink / Paper / Red, знак «тории в энсо с сакурой».
- Тон интерфейса: тихая ночная библиотека. Литературно, сдержанно, без маркетингового шума.

Полная карта страниц, файлов и всех ключей `localStorage` — в `prototype/README.md` (45 КБ). Он актуален: перед работой найти нужный раздел там, а не угадывать.

## Запуск

```powershell
# фронтенд
cd G:\Developing\kuroha\prototype
python -m http.server 4173

# бэкенд (отдельно, если задача про cloud.html / API)
cd G:\Developing\kuroha\server
node server.js          # http://127.0.0.1:4180
```

- Сайт: `http://127.0.0.1:4173/`
- API health: `http://127.0.0.1:4180/api/health`
- CORS в `server.js` разрешает только `127.0.0.1:4173`, `127.0.0.1:4177`, `localhost:4177`. Не меняй порт без правки CORS.
- Открывать файлы напрямую через `file://` нельзя: сломаются fetch, service worker и часть путей.

## Жёсткие правила

1. **Не добавлять зависимости и сборку.** Ни npm-пакетов, ни CDN-скриптов, ни второго шрифта. Единственный внешний ресурс — Google Fonts с Exo 2.
2. **Цвета, отступы, радиусы, тени, тайминги — только из `tokens.css`** (`--kh-*`). Хардкод `#fff`, `12px`, `0.2s` в новом коде запрещён. Новые токены не заводить без явной просьбы: сначала искать подходящий существующий.
3. **Три темы.** `data-theme="night|paper|graphite"` на `<html>` (по умолчанию `night`), читалка дополнительно `data-reader="paper|gray"`. Любой новый цвет проверять во всех темах: он должен читаться на светлом и на тёмном.
4. **Именование классов** — как в проекте: блок и `block__element`, модификатор через `--` (`site-header`, `hero__copy`, `btn--primary`, `cover--lg`). Состояния — `is-active`, `is-open`.
5. **Общие стили — только в `styles.css`**, и только если компонент реально нужен на трёх и более страницах. Специфика страницы живёт в её `page.css` (`clubs.css`, `detail.css`, …). Дублировать общий компонент в page-css нельзя.
6. **Шапка, мобильное меню и футер продублированы во всех 35 HTML.** Поменял навигацию, ссылку, порядок пунктов — обновил **все** страницы. Это самая частая причина рассинхрона.
7. **Порядок скриптов в конце страницы:** `data.js` → `search-data.js` (если нужен поиск) → `app.js` → page-js → `pwa.js`. Все с `defer`, кроме инлайнового скрипта темы в `<head>`.
8. **Версии ассетов.** Подключения выглядят как `styles.css?v=search1`, `tokens.css?v=brand3`. Меняешь общий CSS/JS — подними суффикс `?v=` во всех страницах, иначе браузер и service worker отдадут старую версию. Аналогично подними `CACHE_NAME` в `sw.js` (`kuroha-v77`) при изменении предкэшируемых файлов.
9. **Состояние — только `localStorage`, ключи строго `kuroha-*`.** Полный список в README, раздел «Локальные данные». Никаких `fetch` на сервер, кроме `cloud.js`/`server`, и никакой аналитики.
10. **События изменений.** После записи состояния страница шлёт `document.dispatchEvent(new CustomEvent("kuroha:<name>-change"))`; другие страницы слушают. Новый ключ — новое событие по той же схеме.
11. **Тексты не переписывать без просьбы.** Русский язык, «ты»-обращение, без англицизмов и без восклицательных знаков.
12. **Не рефакторить «заодно».** Diff должен содержать только файлы, нужные для задачи. Соседние страницы, форматирование и «улучшения» — не трогать.

## Данные и демо-контент

- Тайтлы: `data.js` (30 историй), жанры и подборки: `discover-data.js`, читатели: `readers-data.js`, команды: `teams-data.js`, клубы: `clubs-data.js`, публичные списки: `public-lists-data.js`, цитаты: `quotes-data.js`, поисковый индекс: `search-data.js`.
- Все тайтлы, авторы и главы вымышлены. Не заменять их реальными произведениями и не добавлять реальные обложки.
- Демо-данные инициализируются один раз и помечаются ключами `*-seeded` (`demo` / `user` / `cleared`). Не ломать эту логику: пользователь должен иметь возможность очистить демо и не получить его обратно.

## Границы прототипа

Авторизация, модерация, реальные загрузки и ридер изображений не сделаны. Админка — локальная симуляция. Всё «серверное» — учебный backend без TLS, rate limit и нормальной БД. Не выдавать это за готовый продукт и не расширять бэкенд без явной просьбы.

## Как работать над задачей

1. Прочитать `tokens.css` и 1–2 соседние страницы того же типа — они задают образец.
2. Определить минимальный набор файлов: обычно `page.html` + `page.css` (+ `page.js`). Общий `styles.css` — только по правилу 5.
3. Сделать правку.
4. Проверить в браузере: 1280 px и 360 px, все три темы, пустое состояние (нет данных в `localStorage`), консоль без ошибок.
5. Перечитать собственный diff: нет ли случайных файлов, хардкод-цветов, забытых `?v=`.
